## Introduction

Amazon GuardDuty provides continuous monitoring and threat detection across multiple AWS services, helping you identify potentially malicious activity before it can cause significant damage to your environment.

---

## RDS Protection Finding Types

GuardDuty RDS Protection monitors database login activity for potential access threats to your Amazon Aurora and RDS databases.

| Finding Type | Severity | Description |
|--------------|----------|-------------|
| `CredentialAccess:RDS/TorIPCaller.FailedLogin` | Medium | Failed login attempt from Tor exit node |
| `Discovery:RDS/TorIPCaller` | Medium | Tor IP probed database (no login attempt) |
| `Discovery:RDS/MaliciousIPCaller` | Medium | Malicious IP probed database |

> 📚 [Complete list of RDS findings](https://docs.aws.amazon.com/guardduty/latest/ug/guardduty_finding-types-rds.html)

---

## IAM Protection Finding Types

GuardDuty detects potentially anomalous behavior and unauthorized IAM activity using CloudTrail management events.

| Finding Type | Severity | Description |
|--------------|----------|-------------|
| `Recon:IAMUser/MaliciousIPCaller.Custom` | Medium | API invoked from malicious IP on custom threat list |
| `Recon:IAMUser/TorIPCaller` | Medium | API invoked from Tor exit node |

> 📚 [Complete list of IAM findings](https://docs.aws.amazon.com/guardduty/latest/ug/guardduty_finding-types-iam.html)

---

## EC2 Threat Detection Finding Types

GuardDuty monitors EC2 instances using VPC Flow Logs, DNS logs, and CloudTrail events.

| Finding Type | Severity | Description |
|--------------|----------|-------------|
| `UnauthorizedAccess:EC2/SSHBruteForce` | Low/High | SSH brute force attack detected |
| `Backdoor:EC2/C&CActivity.B!DNS` | High | Instance querying command & control server |
| `UnauthorizedAccess:IAMUser/InstanceCredentialExfiltration.OutsideAWS` | High | EC2 credentials used from external IP |

> 📚 [Complete list of EC2 findings](https://docs.aws.amazon.com/guardduty/latest/ug/guardduty_finding-types-ec2.html)

## Checking Findings in GuardDuty Console

### Step 1: Navigate to GuardDuty Console

1. In your AWS account, browse to [**GuardDuty**](https://console.aws.amazon.com/guardduty/)
2. GuardDuty is already enabled in your account and you will land on the Summary page

### Step 2: View Findings

1. On the left side, click on **Findings**
2. Here you'll find all of the findings generated by GuardDuty in this region

![GuardDuty Findings Page](../../static/module4-picture-1.png)

### Step 3: Review RDS Finding Details

For example, if you click on the title of a `Discovery:RDS/MaliciousIPCaller` type finding, it will show complete details on the right panel:

![RDS Finding Details](../../static/module4-picture-2.png)

Under the **"Actor"** field you will be able to see the IP address performing this activity.

### Step 4: Review IAM Finding Details

Similarly, if you check a `Recon:IAMUser/TorIPCaller` type finding, you can see the details under the **'Affected resources'** section. Further scroll down to see the **'API calls'** section to see which API call(s) were made, when, and how many times.

![IAM Finding Details](../../static/module4-picture-3.png)

### Step 5: Review EC2 SSH BruteForce Findings

Filter by finding type: `UnauthorizedAccess:EC2/SSHBruteForce`

When examining SSH BruteForce findings, review:
- **Severity Level:** High severity indicates sustained attacks
- **Source IP:** Attacking IP address and geolocation
- **Target Instance:** Affected EC2 instance details
- **Attack Pattern:** Frequency and timing of attempts

![SSH BruteForce Finding Overview](../../static/4.1-ssh_bruteforce_overview.png)

### Step 6: Review EC2 Tor Client Findings

Filter by finding type: `UnauthorizedAccess:EC2/TorClient`

When examining Tor Client findings, analyze:
- **Connection Frequency:** Number of connections to Tor network
- **Tor Entry Node:** Geographic location and hosting provider
- **Time Span:** Duration of Tor activity
- **Port Analysis:** Ports used for Tor communication

![Tor Client Finding Overview](../../static/4.2-tor_client_overview.png)

### Step 7: Review Credential Exfiltration Findings

Filter by finding type: `UnauthorizedAccess:IAMUser/InstanceCredentialExfiltration.OutsideAWS`

When examining credential exfiltration findings, examine:
- **Instance Identity:** The compromised EC2 instance
- **IAM Role:** The role with exfiltrated credentials
- **External IP:** IP address using stolen credentials
- **API Calls:** Specific AWS APIs being called externally

![Credential Exfiltration Overview](../../static/4.3-credential_exfiltration_overview.png)

## Key Observations

When reviewing GuardDuty findings, pay attention to:

1. **Finding Type**: Indicates the nature of the threat (RDS login attempts, IAM reconnaissance, EC2 attacks, etc.)
2. **Severity**: Helps prioritize response actions (Low, Medium, High)
3. **Actor Information**: Source IP address, geolocation, and whether it's from a known malicious source or Tor network
4. **Resource Details**: Which database, instance, or IAM entity was targeted
5. **Action Details**: What specific actions were attempted (login, API calls, network connections, etc.)
6. **Timestamp**: When the activity occurred
7. **Correlation**: Look for patterns across multiple findings affecting the same resources

## Best Practices for Security

### RDS Security

1. **Network Isolation**: Place RDS instances in private subnets within a VPC
2. **Security Groups**: Implement least-privilege security group rules
3. **Authentication**: Use IAM database authentication where possible
4. **Encryption**: Enable encryption at rest and in transit
5. **Monitoring**: Enable Enhanced Monitoring and Database Activity Streams

### EC2 Security

1. **Patch Management**: Keep instances updated with latest security patches
2. **SSH Hardening**: Use SSH keys instead of passwords, disable root login
3. **Network Segmentation**: Use security groups and NACLs effectively
4. **IMDSv2**: Require IMDSv2 for instance metadata access
5. **Monitoring**: Enable VPC Flow Logs and CloudWatch monitoring

### IAM Security

1. **Least Privilege**: Grant only the permissions necessary for users to perform their tasks
2. **MFA**: Enable multi-factor authentication for all users
3. **Credential Rotation**: Regularly rotate access keys and passwords
4. **Access Review**: Periodically review and audit IAM permissions
5. **CloudTrail**: Ensure CloudTrail is enabled to log all API activity

## Troubleshooting

### Issue: No findings visible in GuardDuty
**Solution:**
1. Findings may take 15-30 minutes to appear after workshop starts
2. Ensure you're in the us-west-2 region
3. Check that GuardDuty is enabled (should show "Enabled" status)

### Issue: Findings show as "Archived"
**Solution:** Click "Current" in the findings filter to see active findings only.
